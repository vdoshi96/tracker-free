Architecture

Design objective

RECOMMENDATION: Prefer a false skip to clipboard corruption or functional-link damage. Every state transition is serialized, every transformation is bounded and synchronous, and every uncertainty returns a no-write decision.

Core values include PasteboardGeneration, PasteboardRepresentation, PasteboardSnapshot, EligibleClipboardValue, RuleSetSnapshot, CleanDecision, CleanResult, RemovedParameter, UndoToken, OperationalState, PermissionState, PauseState, and ConflictState.

RECOMMENDATION: These values are immutable and Sendable where they cross isolation. NSPasteboard and NSPasteboardItem remain inside the main-actor adapter call.

Startup and timers

  1. Load scalar preferences and atomically validate local custom rules.
  2. Default requested enablement to off on a true first launch.
  3. Set lastObservedGeneration to the current General-pasteboard changeCount.
  4. Do not inspect or clean the preexisting clipboard.
  5. Clear clipboard-derived RAM.
  6. Determine guarded pasteboard access behavior where the API is available.
  7. Attach workspace sleep, wake, session, logout, and termination observers.
  8. Run a 250 ms timer with 25–50 ms tolerance while operational; otherwise run a one-second count-only timer.

RECOMMENDATION: Disabled, paused, permission-blocked, sleeping, session-inactive, and conflict-paused states never inspect items or content.

Automatic generation state machine

  1. Read only changeCount as generation G.
  2. Return if G is already observed; otherwise record it.
  3. Suppress only when G equals the exact app-owned generation.
  4. Invalidate stale undo when a new external generation appears.
  5. Return without content access unless automation remains operational.
  6. Capture immutable rule revision R.
  7. Require exactly one item and inventory all advertised types.
  8. Reject unsupported types before materializing text.
  9. Materialize only allowed representations, then reject any read that exceeded the size or 100 ms post-read duration bound.
  10. Recheck changeCount == G after every potentially lazy read.
  11. Recognize, protect, and synchronously transform under R.
  12. Return without writing when output bytes are identical.
  13. Consume Skip Next only when a stable eligible value would otherwise change.
  14. Recheck generation, rule revision, and operational state.
  15. Build the complete fresh replacement item.
  16. Commit synchronously and record only privacy-safe result metadata.

RECOMMENDATION: A generation is processed at most once. Content equality never suppresses a later external generation.

Eligibility and representation policy

An item is eligible only when:

  • pasteboardItems.count == 1.
  • Advertised content consists only of public.utf8-plain-text and/or public.url.
  • At least one allowed representation exists.
  • Combined allowed data is at most 64 KiB and valid UTF-8.
  • If both exist, the stripped plain-text URL core equals the URL representation exactly.
  • Every materialized value matches the original inventory while generation ownership remains unchanged.

Plain text may have an exact edge envelope: ASCII spaces/tabs before the URL, then ASCII spaces/tabs and at most one final LF or CRLF after it. The accepted envelope is preserved byte-for-byte.

Hard skips include HTML, RTF/RTFD, images, files, file promises, unknown/private/custom types, multiple items, failed or unstable lazy values, concealed/transient/autogenerated/remote markers, and a private Tracker Free marker on a non-owned generation.

OPEN: NSPasteboardItem.data(forType:) is synchronous and has no public cancellation API. The implementation can reject a provider that returns after 100 ms, but cannot preempt that call or prevent it from allocating before it returns.

INFERENCE: Concealed, transient, autogenerated, and remote identifiers are maintained community conventions rather than a complete official Apple contract.

URL recognizer

The core must:

  • Be ASCII only and begin case-insensitively with http:// or https://.
  • Have a nonempty canonical host and a valid explicit port when present.
  • Contain no userinfo, backslash, NUL/control, malformed %HH, internal whitespace, or second literal HTTP(S) URL.
  • Not be scheme-relative, a non-HTTP scheme, an IP literal, loopback/private/local target, .local, or a single-label host.
  • Pass strict Foundation component inspection without Foundation repairing its spelling.
  • Fit within 64 KiB total, with at most 8 KiB each for the raw path and fragment.

Domain comparison is ASCII case-insensitive after canonical extraction and uses exact equality or a dot boundary. Path matching uses original percent-encoded segments; ambiguity preserves.

For whole-link classification only, each path component is strictly percent-decoded once. A decoded . or .., residual %, C0/DEL byte, slash, or backslash makes the classification path ambiguous and protects the entire URL. The original raw path remains the only output authority.

RECOMMENDATION: ASCII Punycode may pass. Literal Unicode URLs remain unchanged in version 1.

Raw query surgery

  1. Split at the first literal # and preserve the fragment exactly.
  2. Find the first literal ? before that fragment.
  3. Return no-write when the query is absent/empty or no field is removable.
  4. Fail open when the raw query contains a literal semicolon.
  5. Split on literal &, retaining empty subsequences.
  6. Split each field at its first literal =.
  7. Strictly percent-decode only the field name for matching; never translate +, decode a value, or permit non-ASCII decoded names.
  8. Apply one decision to every duplicate occurrence.
  9. Remove approved whole fields in all name, name=, and name=value forms.
  10. Rejoin retained exact fields with &.
  11. Remove ? only when no structural field remains; an empty retained field still preserves the delimiter.
  12. Reattach the exact fragment and envelope and strictly validate again.
  13. Assert byte-identical scheme, authority, path, fragment, and envelope; retained fields must be an exact ordered subsequence.

The raw query is capped at 256 fields. Whole-link protection inspection is capped at 128 path components and 128 fragment fields. Exceeding any structural bound preserves the input unchanged.

RECOMMENDATION: Never emit a mutated URL, URLComponents.string, query, or query-item collection.

Commit and rollback

  1. Make the final generation check.
  2. Enter a tiny synchronous section with no await, log, UI callback, or rule lookup.
  3. Call prepareForNewContents(with: .currentHostOnly).
  4. Write one newly constructed item with expected allowed values and com.vishal.TrackerFree.cleaned-v1.
  5. Capture the actual final generation, which must not be inferred from an increment count.
  6. While that generation remains current, read back the expected values and marker.
  7. If write/readback fails and the app still owns the affected generation, immediately attempt an eager .currentHostOnly rollback.
  8. Never roll back after another owner changes the generation.

On verified success, record the exact owned generation, cleaned allowed values, and one RAM-only undo token. On uncertainty, expose a generic failure and never claim success.

OPEN: Public pasteboard APIs cannot eliminate the final-check/ownership micro-race or the process-death interval after clearing.

Pause, skip, undo, and conflict

  • Requested enabled state persists; re-enable baselines without cleaning current content.
  • Timed pause persists a wall-clock expiration and uses a monotonic/suspending clock while running where practical.
  • Indefinite pause persists until explicit resume.
  • Skip Next is RAM-only and is consumed only at the would-change decision for an external stable eligible unprotected URL.
  • Manual clean bypasses requested enablement, pause, and Skip Next but never bypasses safety.
  • Undo requires exact generation, allowed-output values, and private marker equality immediately before restore.
  • Restore uses .currentHostOnly, removes the marker, records the restore generation as owned, and clears the token.
  • A bounded short-lived RAM ring detects three identical app-produced original/output pairs within two seconds and enters conflict pause.
  • Conflict pause requires explicit user recovery; an unrelated generation increment never resumes automatic cleaning.

VERIFIED: Sleep and session loss wipe the clipboard-derived pair ring and undo state but preserve an already-entered conflict-pause flag. Wake and session activation baseline without reading and remain conflict-paused; only explicit resume clears that state. Termination or process exit clears all RAM state.

RECOMMENDATION: The conflict ring is the narrow exception to immediate generation cleanup: retain only the smallest two-second pair window and never a hash.

Lifecycle

Sleep, session resignation, logout, or termination cancels pending work, invalidates undo, and wipes clipboard-derived RAM. Wake and activation baseline current generation and never clean content copied while inactive. Relaunch loses undo and Skip Next.

Operational and UI state

RECOMMENDATION: The coordinator is the single source of truth. Requested “Enabled” is distinct from operational “Automatic cleaning: On”; permission, pause, sleep/session, and conflict states must be visible and truthful.

The menu ordering and result language are specified in Project and Privacy. Settings owns onboarding, rules, import/export/reset, privacy disclosures, login-item status, and Shortcut guidance.
